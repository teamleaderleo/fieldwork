# Upstream Profile

Kernel: [`KERNEL.md`](../KERNEL.md)

## Use this profile when

The assignment observes, compares, or prepares material concerning a third-party project, contribution policy, issue, pull request, commit, discussion, or public proposal.

## Default boundary

External observation is quiet research.

Without exact user authority for the specific interaction, do not:

- open or edit an upstream issue, pull request, discussion, review, comment, or reaction;
- submit a patch, proposal, email, form, or other public communication;
- use interaction text that creates an accidental third-party backlink;
- imply maintainer interest, acceptance, priority, or policy not supported by primary evidence.

Creating a Fieldwork issue, finding, fork branch, proposal packet, or candidate diff does not authorize upstream contact.

## Reference handling

In GitHub interaction text within controlled repositories:

- use `redirect.github.com` for third-party issue, pull-request, discussion, and commit links;
- remove third-party owner/repository shorthand references;
- use an intentional-upstream marker only for the exact authorized interaction.

Tracked repository files may use ordinary direct links when they do not create interaction backlinks. Continue to cite primary sources and record the exact claim, revision or date, and limitation.

## Quiet research procedure

1. Pin the public source revision or retrieval boundary.
2. Read current source, tests, history, contribution instructions, and relevant first-party material.
3. Search for duplicates and adjacent prior art without contacting maintainers.
4. Separate documented policy from inference.
5. Keep proposal wording, candidate code, and evidence in owned repositories.
6. Refresh contribution and AI-disclosure policy before any later authorized submission.
7. Treat public-head movement as a freshness event; preserve historical receipts but expire currentness claims as required.

## Authorized interaction

When the user authorizes one exact external action:

- record the scope of authority;
- review the exact current text, diff, target, identity, disclosure, and attachments;
- perform only the authorized action;
- record the resulting public reference and any changed obligation;
- do not generalize the authority to follow-up comments, revisions, or another repository.

Technical readiness never grants upstream authority.
