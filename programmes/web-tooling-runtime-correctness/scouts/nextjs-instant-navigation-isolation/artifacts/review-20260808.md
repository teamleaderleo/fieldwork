## Review findings

### Finding 1 — current cleanup has a real ownership mismatch

`instant()` resolves one application URL and acquires `next-instant-navigation-testing` for that URL's hostname. Its cleanup helper calls unfiltered `BrowserContext.cookies()` and expires every cookie with that name in the browser context.

Real Playwright/Chromium evidence retained in `playwright-cookie-scope-browser.json` confirms that unfiltered lookup returns matching entries from unrelated domains and that expiring those returned entries removes both. URL-filtered lookup returns only cookies applicable to the requested URL and preserves the unrelated origin.

The package README also describes the protocol as one ordinary cookie set and cleared with `document.cookie`, which is naturally scoped by cookie applicability. This supports treating the acquired application URL as the cleanup identity.

### Finding 2 — `context.cookies(scopeURL)` is compatible with the existing Playwright API surface

Playwright documents the optional URL filter on `BrowserContext.cookies` from the same early API generation as the method itself. The candidate therefore does not introduce a newer cookie-query primitive than the helper already depends on in practice.

### Finding 3 — the first regression test was prepared incorrectly

The first candidate added a separate e2e test file by hand. Current Next.js `AGENTS.md` requires new test suites to be generated through `pnpm new-test` and says closely related checks should live in the existing suite.

Review repair: the standalone test file was removed. The correct target-native regression should be added to `test/e2e/app-dir/instant-navigation-testing-api/instant-navigation-testing-api.test.ts`, beside stale-cookie recovery and BrowserContext ownership tests.

### Finding 4 — keep active-scope ownership separate

PR 95375 deliberately keys concurrent `instant()` exclusion by `BrowserContext`. This review does not change that behavior. The candidate only narrows which cookie entries cleanup may delete.

That split is useful because the evidence for cookie deletion is stronger than the case for distinct-origin concurrent scopes.

## Candidate behavior

Current:

```text
scopeURL = app A
context.cookies()
  -> A instant cookie
  -> B instant cookie
cleanup expires A + B
```

Candidate:

```text
scopeURL = app A
context.cookies(scopeURL)
  -> cookies applicable to A
cleanup expires A-applicable instant entries
B-only instant cookie survives
```

The URL filter also handles normal cookie semantics correctly: parent-domain cookies that genuinely apply to A remain in the cleanup set; secure/path cookies that do not apply to A stay outside it.
