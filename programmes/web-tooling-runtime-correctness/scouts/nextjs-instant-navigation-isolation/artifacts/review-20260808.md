## Review findings

### Finding 1 — current cleanup has a real ownership mismatch

`instant()` resolves one application URL and acquires `next-instant-navigation-testing` for that URL's hostname. Its cleanup helper calls unfiltered `BrowserContext.cookies()` and expires every cookie with that name in the browser context.

Real Playwright/Chromium evidence retained in `playwright-cookie-scope-browser.json` confirms that unfiltered lookup returns matching entries from unrelated domains and that expiring those returned entries removes both. URL-filtered lookup returns only cookies applicable to the requested URL and preserves a cookie that is unrelated to that URL.

The package README describes the protocol as one ordinary cookie set and cleared with `document.cookie`, which follows normal cookie applicability. This supports treating the resolved application URL as the cleanup identity.

### Finding 2 — `context.cookies(scopeURL)` fits the existing Playwright API surface

Playwright documents the optional URL filter on `BrowserContext.cookies` from the same early API generation as the method itself. The candidate therefore does not add a newer practical cookie-query dependency than the helper already uses.

The URL filter is also preferable to manual domain comparison because it delegates path, secure, and parent-domain applicability to Playwright.

### Finding 3 — the first regression test was prepared incorrectly and was removed

The first candidate added a separate e2e test file by hand. Current Next.js `AGENTS.md` requires new suites to use `pnpm new-test` and says closely related checks should live in the existing suite.

Review repair: the standalone test file was deleted. The correct regression belongs in `test/e2e/app-dir/instant-navigation-testing-api/instant-navigation-testing-api.test.ts`, beside stale-cookie recovery and BrowserContext ownership coverage.

### Finding 4 — active-scope ownership stays separate

PR 95375 deliberately keys concurrent `instant()` exclusion by `BrowserContext`. This review preserves that behavior. The candidate only narrows which cookie entries cleanup may delete.

The inherited source comment previously justified context-wide activity by saying the cookie itself was context-scoped. Review repair removed that inaccurate rationale while retaining the existing concurrency rule.

## Candidate behavior

Current:

```text
scopeURL = app A
context.cookies()
  -> A instant cookie
  -> B-only instant cookie
cleanup expires A + B
```

Candidate:

```text
scopeURL = app A
context.cookies(scopeURL)
  -> cookies applicable to A
cleanup expires A-applicable instant entries
B-only instant cookie survives
```

A parent-domain cookie that genuinely applies to A remains in the cleanup set. A cookie whose domain/path/security attributes make it inapplicable to A remains outside the set.
