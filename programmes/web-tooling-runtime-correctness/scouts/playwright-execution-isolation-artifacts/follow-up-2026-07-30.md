## Stronger findings

### 1. Fixture teardown resumption remains the lead core-runner candidate

The current core fork retains the same teardown behavior as the pinned scout revision:

- a fixture checks whether its shared teardown slot is exhausted before starting its teardown body;
- the `finally` block removes the fixture from dependency tracking and `instanceForId` whether the body ran or skipped;
- a later worker-cleanup `teardownScope('test')` therefore has no fixture record to revisit.

The retained test uses two independent test-scoped fixtures. `blocker` exhausts the shared after-hooks slot. `sentinel` must log one cleanup marker on attempt zero and retry one. The expected current result is zero sentinel markers.

### 2. MCP and CLI can advertise a video file whose recording never began

The shared backend records a derived video filename before `page.screencast.start()` succeeds. For pages created after recording begins, start failures are caught and discarded. `stopVideoRecording()` returns the recorded filenames, and `Response.addFileResult(..., null)` emits links without checking that the file exists or is a regular file.

This creates a concrete false-positive artifact receipt:

1. start video successfully;
2. make the derived `video-1.webm` path unusable;
3. create a second tab;
4. let its screencast start fail;
5. stop video;
6. observe a link for `video-1.webm` despite failed recording startup.

Experiments:

  - file: `tests/video-finalization-receipt.spec.ts`
  - commit: `be384517f0f5d10ee419786fc2b10f357a82da92`
- CLI fork PR: `teamleaderleo/playwright-cli#1`
  - branch: `fieldwork/video-finalization-receipt-probe`
  - file: `tests/video-finalization-receipt.spec.ts`

Campaign consequence: agents, reporters, and users can treat an unusable artifact link as a completed recording. The smallest correction records a file only after startup succeeds and validates completion before emitting the link. A richer correction emits `completed`, `start-failed`, `stop-failed`, or `missing` receipts.

### 3. Python async shutdown loses retriability when the first stop is cancelled

`PlaywrightContextManager.__aexit__` sets `_exit_was_called = True` before awaiting `Connection.stop_async()`. If cancellation interrupts `wait_until_stopped()`, later calls to `playwright.stop()` return immediately. The connection can therefore miss `cleanup()`, leaving `_closed_error` unset and protocol callback cleanup incomplete even after the driver transport stops.

The retained test blocks `wait_until_stopped()`, cancels the first stop task, releases the transport, retries stop, and requires connection cleanup to have completed.

Experiment:

- fork PR: `teamleaderleo/playwright-python#1`
- branch: `fieldwork/async-stop-cancellation-probe`
- file: `tests/async/test_async_stop_cancellation.py`
- commit: `c81f671af0adac2b866d8255e2f802ae0aba9ece`

Campaign consequence: cancellation can turn an idempotent-looking public stop method into a completed no-op while internal cleanup remains incomplete. The smallest correction marks exit complete only after cleanup, or stores and re-awaits one shutdown task while shielding the cleanup phase from caller cancellation.

### 4. Blob reporting remains all-or-nothing before `onEnd`

The blob reporter retains events in memory and creates its ZIP during `onEnd`. An abrupt process exit after `onTestEnd` loses completed attempt events and attachment references because no durable journal exists yet.

The retained core test configures blob reporter first and a second reporter that exits the process from `onTestEnd`. It requires a parseable `report.partial.jsonl` containing the events already observed by the blob reporter.

Experiment:

- fork PR: `teamleaderleo/playwright#2`
- branch: `fieldwork/blob-report-journal-probe`
- file: `tests/playwright-test/reporter-blob-interruption.spec.ts`
- commit: `77c2007bf7ffdd00f617916164cc5fa6ec7946a3`

Campaign consequence: a completed test attempt can leave traces, screenshots, or videos on disk with no report that indexes them. A temporary append-only JSONL journal plus an atomic final ZIP gives interrupted runs a recoverable state.

## Narrowed or weakened candidates

### Worker force-kill during graceful teardown

Core commit `63ff5dc1b3a379a07da51315ff439dcea3bc479b` added child heartbeats during graceful shutdown and changed the parent watchdog to force-kill only after heartbeat silence. This directly addresses slow fixture teardown with `timeout: 0`.

The remaining process-tree case requires genuine heartbeat loss: event-loop blockage, worker crash, IPC loss, or parent death. Keep it as a bounded exact-runner probe below the four candidates above.

### CLI close acknowledgement race

The daemon invokes browser cleanup before sending the stop acknowledgement. If the acknowledgement is lost, the client treats socket closure as successful session close. This path carries stronger cleanup ordering than the initial scout inferred. No campaign is recommended here without a concrete survivor or locked-profile reproduction.
