## Acceptance boundary for a repair

A minimum repair should make all of these deterministic properties explicit:

1. An already-aborted signal prevents a new subprocess from being started.
2. Abort after spawn initiates termination of the parent and descendants.
3. The invocation retains ownership until process exit or a bounded escalation outcome.
4. The abort listener is removed on every terminal path.
5. Partial stdout and stderr produced before abort remain available in the terminal result.
6. Repeated abort or close events cannot settle the invocation twice.
7. Sandbox cleanup runs after process ownership is released.

The first test proves only property 2. Additional tests should be added one property at a time rather than allowing one broad mock to stand in for the complete lifecycle contract.
