### Unconfigured browser acquisition

Creates a browser-WebGPU surface but never configures it.

Prepared assertions:

```text
public Surface::get_configuration = None
raw GPUCanvasContext.getConfiguration = null
public Surface::get_current_texture = Lost
raw GPUCanvasContext remains unconfigured
```

Source basis:

- raw `getCurrentTexture` throws for an unconfigured context;
- the browser backend catches every raw acquisition exception and maps it to `Lost`;
- public `Lost` guidance says surface recreation, although configuration is the missing operation here.

This exposes a browser-specific typed recovery mismatch. Native core routes acquisition errors through validation handling when an error sink exists and treats a pre-configuration error as fatal when no configured device/error sink exists.

## Partial-state finding

The browser backend sets canvas width and height before validating present mode, alpha mode, color space, or calling raw `GPUCanvasContext.configure`.

For the locally rejected color-space path, source predicts:

```text
raw accepted configuration = earlier baseline
canvas extent = rejected request
public configuration cache = rejected request
configure_failed = true
public acquisition = Lost
raw acquisition = usable at resized extent
```

The state is therefore not complete preservation of the prior configuration. Some externally observable fields mutate before rejection.

## Related source consequences

### Native public metadata

Native core can preserve an earlier accepted presentation after validation rejection while the public wrapper caches the request. Public texture descriptors are built from that cache. A private wrapper characterization and a real core-backed control remain necessary.

### Acquisition exception classification

The browser backend maps all raw `getCurrentTexture` exceptions to `Lost`. Before changing the public result, tests must distinguish invalid state, device loss, internal/out-of-memory failure, and transient browser exceptions.

### Presentation outcome

Public `Queue::present` marks a frame presented before backend present, and backend present returns no result. Native errors are routed to an error sink. Presentation failure and public ownership transfer are therefore separate states worth later fault injection.
