# Nixpkgs gomarkdoc check restoration

## In simple words

Nixpkgs builds gomarkdoc 1.1.0 with its tests disabled. The original reason is real: Nix injects `-mod=vendor`, and gomarkdoc's command tests parse that package-manager setting as application input.

Removing the flag alone exposed two more release assumptions. The retained repair uses supported Go 1.25 for both the binary and tests, removes only `-mod=vendor` during checks, and creates the empty config fixture missing from the release tag. The full package and version checks passed on Linux and Darwin.

## Input → action → result

### Baseline containment

Input: gomarkdoc 1.1.0 under current `buildGoModule`.  
Action: `doCheck = false`.  
Result: package builds without upstream coverage.

### Hypothesis A — environment-only repair

Input: current Go 1.26.5 builder.  
Action: enable checks and remove only `-mod=vendor`.  
Result: both platforms entered the real test phase and cleared the original parser collision, then failed on a missing `.gomarkdoc-empty.yml` fixture and a documentation-link golden changed by Go 1.26.

### Hypothesis B — coherent compatibility restoration

Input: the same exact Nixpkgs and gomarkdoc revisions.  
Action: use `buildGo125Module` for build and test, remove `-mod=vendor`, and create the omitted empty fixture in the disposable tree.  
Result: full package checks and `gomarkdoc.tests.version` passed on x86_64-linux and aarch64-darwin.

## Retained target patch

```nix
{
  buildGo125Module,
  ...
}:

buildGo125Module (finalAttrs: {
  doCheck = true;

  preCheck = ''
    export GOFLAGS="''${GOFLAGS//-mod=vendor/}"
    touch .gomarkdoc-empty.yml
  '';
})
```

The vendor tree remains materialized and the shared builder keeps `GOPROXY=off`. The empty fixture exists only in the temporary source tree and is not installed.

## Why the same toolchain matters

The failed golden describes documentation generated by the final binary. Testing with Go 1.25 while shipping Go 1.26 would validate a different behavior. The retained candidate therefore selects the same supported Go generation for compilation and tests.
