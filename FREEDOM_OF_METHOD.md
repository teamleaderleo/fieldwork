# Freedom of Method

## In simple words

Fieldwork names the result, hard boundaries, evidence, and decision. Workers choose the route: tools, sequence, depth, voice, and presentation. Good work can look different from previous work.

## Read instructions by level

Fieldwork guidance uses four levels:

1. **Boundary** — a binding limit involving authority, privacy, safety, ownership, cost, or claim accuracy.
2. **Required outcome** — a result that must be demonstrated for the requested transition.
3. **Default** — a proven starting point that workers may adapt when another route serves the work better.
4. **Example** — one possible expression, sequence, file layout, command, or wording.

When a document leaves the level unstated, treat safety, authority, privacy, ownership, and factual accuracy as boundaries. Treat templates, ordered lists, headings, file layouts, and sample wording as defaults unless a validator or assignment explicitly depends on them.

A new instruction should say which level it occupies. Requirements earn their place by naming the failure they prevent.

## Freedom inside an assignment

Within the assigned question and authority boundary, a worker may:

- choose tools, commands, order, and investigative technique;
- follow evidence into a better bounded route;
- combine records when one durable account serves the readers;
- split records when different readers need different levels of detail;
- replace a template with equivalent evidence;
- use prose, code, diagrams, tables, traces, or a mixture;
- write in a natural voice suited to the audience;
- simplify repeated ceremony and retire duplicate records;
- continue through ordinary repair, review, and evidence transfer.

Record a departure from a familiar default when it changes how the next person should interpret, reproduce, or continue the work.

## The minimum durable result

The next reader should be able to recover:

- the current answer or concrete question;
- the evidence supporting it;
- the limits, uncertainty, and competing explanations;
- the next decision or completion state;
- the authority boundary when external interaction is possible.

No universal number of files, headings, tables, receipts, or comments serves every result. Use the smallest durable account that carries those facts cleanly.

## Writing and presentation

Lead with what the intended reader came to learn. Put proof close enough to inspect, or link to the retained receipt.

Fieldwork often serves three readers:

- a reader seeking the current answer;
- a reviewer testing the reasoning;
- an operator reproducing the exact run.

Those views may be sections in one document, separate files, generated receipts, or links. Choose the lightest arrangement that keeps each view legible.

`## In simple words` is a useful default entry point. A proposal sentence, question, diagram, table, or clearer audience-specific heading can serve the same purpose. Preserve the author’s voice while improving accuracy, clarity, and consequence. Ritual repetition weakens the signal; state stable facts once and link to them elsewhere.

## Review language

Review feedback belongs to one of three levels:

- **Blocking finding** — a concrete defect, unsupported claim, missing evidence, broken boundary, or unsafe transition.
- **Recommendation** — a stronger route, clearer explanation, useful control, or maintainability improvement.
- **Presentation preference** — taste in wording, order, naming, or visual form.

Only a blocking finding prevents the requested transition. A blocking review should name the observed risk, the evidence, and the outcome required for clearance. The author chooses the repair unless the assignment or boundary requires an exact mechanism.

Review the work that exists. A different method, voice, or layout passes when it carries the required result and protections.

## Workflow lifecycle

Automation should validate contracts and report facts. It should leave judgment, prose, and investigative method open.

Choose a repository script or local command when ordinary execution is sufficient. Add a GitHub Action when hosted platforms, permissions, event behavior, retained artifacts, or a remote matrix provide essential evidence.

Every research-specific workflow should declare whether it is:

- **reusable validation**, tied to retained repository-owned inputs; or
- **execution-only**, tied to an exact source head and evidence run.

Execution-only workflows retire after their receipts reach the canonical record. Reusable workflows should run against current repository-owned inputs and avoid abandoned branches or mutable external heads.

## Maintaining the guidance

Before adding a rule, answer:

- Which failure does this prevent?
- Why does existing guidance leave that failure exposed?
- Is this a boundary, required outcome, default, or example?
- When can this rule retire?

Prefer one clear rule over parallel restatements. Fold recurring lessons into the nearest durable guide, remove stale procedures, and leave room for the next worker to find a better way.
