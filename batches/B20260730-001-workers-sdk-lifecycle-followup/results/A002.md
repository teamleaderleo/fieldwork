## In simple words

Wrangler and the Cloudflare Vite plugin can start from the same directory and choose different Wrangler configuration files. The difference is not limited to one extension: they use different extension order, different directory-search boundaries, and different generated-config redirect behavior.

## Strongest finding

The two tools currently implement different selection policies:

- Workers Utils, used by Wrangler, searches upward once per extension in the order `wrangler.json`, `wrangler.jsonc`, then `wrangler.toml`.
- The Vite plugin checks only the configured Vite root in the order `wrangler.jsonc`, `wrangler.json`, then `wrangler.toml`.
- Wrangler callers may opt into `.wrangler/deploy/config.json` and select a generated deployment configuration.
- Vite resolves a concrete source configuration path and passes it explicitly into Wrangler's config reader, which bypasses redirect discovery.

These policies are individually coherent, but their combined effect is not exposed as one inspectable contract.

## Classification

### Intentional or defensible

The Vite plugin's root-only boundary is defensible because Vite owns an explicit project root and should not necessarily inherit a configuration from an unrelated parent workspace.

An explicit `configPath` taking precedence is also a useful, documented escape hatch.

### Compatibility-sensitive

The opposite JSON/JSONC precedence can change bindings, entry points, environments, and deployment settings without changing the invocation directory.

Workers Utils' format-first upward search means a farther parent JSON file can beat a nearer child JSONC or TOML file. This is a surprising but tested Wrangler policy.

### Insufficiently explicit

Redirect behavior is enabled command-by-command rather than represented as a shared policy. Recent upstream PR `cloudflare/workers-sdk#14897` adds redirect support specifically to `wrangler triggers deploy`, further confirming that redirect adoption remains distributed across callers.

Vite warnings identify the selected config path after selection, but the API does not report the rejected candidates, selection reason, search boundary, or source-versus-generated relationship.

## Recommended repair direction

Do not immediately force Wrangler and Vite onto identical defaults. Introduce a shared configuration-selection policy and result record with explicit fields for:

- requested path;
- search starting directory;
- upward-search boundary;
- extension precedence;
- deploy-config redirect enablement;
- user/source config path;
- selected config path;
- deploy-config path;
- environment passed to normalization;
- stable selection reason: `explicit`, `root-discovery`, `upward-discovery`, or `deploy-redirect`.

Wrangler and Vite may retain different policy values, but tests and diagnostics should make every difference deliberate.

## Negative results and limits

- Environment selection changes normalization after a file is selected; it is not another file-discovery policy in the inspected paths.
- Explicit config paths already provide convergence, so a new override mechanism is unnecessary.
- The exact combined divergence matrix was not found as one existing upstream issue.
- The package test is committed and source-reviewed but unexecuted because this environment cannot materialize the full workspace and dependencies.
- The predecessor dependency-free discovery and redirect probes were executed successfully.

## Handoff

The behavior claim is strong enough for a characterization PR. A default-changing implementation should wait for package execution, compatibility review, and a decision about whether the goal is shared defaults or merely shared policy disclosure.
